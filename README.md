# opencode-auto-handoff

面向 **OhMyOpenCode（OMO）+ OpenChamber** 工作流的会话自动交接技能——为长任务、高上下文消耗的会话提供自动接力能力。

当任务较大、耗时长、上下文占用率高时，本技能会在恰当的时机生成**交接摘要**并开新会话接手，同时彻底清理旧会话的系统状态（goal / todo / continuation / 定时任务），确保旧会话不会被系统反复拉起、也不会与新会话争抢同一批文件。

## 适用场景

### 适用前提（设计边界）

本技能的目标用户是 **OhMyOpenCode（OMO）+ OpenChamber** 工作流的使用者，**并非通用 OpenCode 技能**。设计之初就直接建立在这套环境的能力之上——下表不是"安装时的附加要求"，而是**适用场景本身自带的边界**：

| 组件 | 提供的能力 | 在技能中的作用 |
|---|---|---|
| **OhMyOpenCode**（OMO） | `goal` 机制（`/goal` 命令、`create_goal`/`get_goal`/`update_goal` 工具）；`/stop-continuation`（ralph loop / boulder / todo continuation） | 交接后关闭 goal、停止续跑——防止旧会话被系统拉起继续工作 |
| **OpenChamber** | `session.create` / `session.send` / `session.fork` | 开新会话，并把交接摘要一次注入 |
| OpenCode 本体 | 技能运行载体 | 宿主 |
| PowerShell | 上下文占用率脚本 `scripts/calc_ctx_use_rate.ps1` | 仅"持续工作模式（场景 A）"的自动监测需要 |

其中 **`goal` 与 `/stop-continuation` 由 OMO 提供、会话创建由 OpenChamber 提供，均不是原生 OpenCode 能力**——它们正是本技能能"自动交接 + 防止旧会话复活"的根基。脱离这套环境使用，技能会退化为纯摘要输出模式（见[与 OpenChamber / OhMyOpenCode 的关系](#与-openchamber--ohmyopencode-的关系)），那是越过了设计边界，而非配置缺失。

本技能适用的具体场景：

- **长时间持续开发**：任务较大、耗时较久，用户明确表达"一直做不要停""持续工作"等长期跟进意向。
- **上下文接近上限**：单会话上下文占用率达到阈值（脚本自动监测，见[上下文占用率脚本](#上下文占用率脚本可选)）。
- **多阶段接力**：任务需要跨多个会话接力完成，每个会话聚焦一个阶段。
- **人工切换会话**：用户主动想开新会话继续，本技能负责把当前状态完整交接过去。

## 功能特性

- **自主监测交接**：持续工作模式下，在每个任务段落边界自动查询上下文占用率，按阈值决策是否交接。
- **用户主动交接**：识别"交接 / handoff / 开新会话"等明确指令，直接执行，不反复确认。
- **结构化交接摘要**：自动生成包含「当前状态 / 已确认的事实 / 待处理的工作 / 已知的坑 / 会话目标 / 会话级状态」的交接摘要，让新会话零成本接手。
- **交接后彻底清理**：按固定顺序清理 `/stop-continuation → 清空 todo → 关闭 goal → 停用定时任务 → 验证`，杜绝"旧会话被拉起继续干活"。
- **被拉起防御**：已交接的会话无论以何种方式被再次拉起，都会识别自身已交接状态，拒绝工作并再次清理。

## 安装方式

### 1. 获取技能文件

```bash
git clone git@github.com:niuxiaozu/opencode-auto-handoff.git
```

> 技能内部名称为 `auto-handoff`，因此克隆后请将目录重命名为 `auto-handoff`，保持目录名与技能名一致。

### 2. 放入 OpenCode 技能目录

将整个 `auto-handoff` 目录复制到你的 OpenCode 用户级技能目录：

| 平台 | 技能目录 |
|---|---|
| Windows | `C:\Users\<用户名>\.config\opencode\skills\` |
| macOS / Linux | `~/.config/opencode/skills/` |

最终目录结构如下：

```
~/.config/opencode/skills/
└── auto-handoff/
    ├── SKILL.md
    ├── README.md
    └── scripts/
        └── calc_ctx_use_rate.ps1
```

### 3. 验证安装

在新会话中对助手说"**会话交接**"，若助手响应交接流程则安装成功（技能已加载）。

## 使用方式

技能按以下任一条件自动触发，**无需手动装载**：

1. **持续工作授权（明确）**：用户说"任务可能较大""任务耗时较久""一直做不要停""持续工作""创建/goal目标持续工作"等，或主动设置 /goal 目标 → 技能加载并开启自主监测。
2. **明确交接指令**：用户说"会话交接""handoff""开新会话""换个会话继续"等 → 立即执行交接，不确认、不询问。
3. **模糊交接意向**：意向接近第 2 条但不明确 → 助手先确认"您是想交接到新会话继续吗？"，用户确认后执行。
4. **持续工作模糊意向**：表达接近"持续工作"但不明确（如"挂个任务跑着""帮我盯着这个项目推进完""建个 goal 慢慢搞"）→ 助手先确认"您是要开启持续工作模式吗？我会自动监测上下文占用率，在适当时机生成交接摘要并开新会话接手。"，并套用下面的超时默认开启机制。

**超时默认开启机制（场景 A 模糊确认用，应对用户已离开）：**

- 发出确认后，若直到本会话被再次拉起时仍未收到用户对确认的明确回应（用户已离开 / 设置了 goal / 续跑机制拉起），**默认视为确认开启**并进入自主监测，不再询问。
- 用户明确否定（"不用""不需要""只是问问"）→ 不开启。
- 用户未回应确认但直接下达其他工作指令 → 视为已默认开启，执行指令并保持监测。

> 若用户曾明确表示"别切换""本会话不要交接"，本会话内停止一切自主交接（含持续工作模式的自主监测），仅当用户再次明确说"交接"时才执行。

### 场景 A：持续工作模式（自主交接）

用户授权"持续工作"后（明确授权，或经触发条件第 4 条确认 / 超时默认开启），助手进入自主监测状态：

- 每个小任务收尾（段落边界）执行一次上下文占用率查询：
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File "scripts\calc_ctx_use_rate.ps1" -SessionId <当前会话ID>
  ```
- 按结果决策：

| 占用率 | 行为 |
|---|---|
| ≥ 45% | 立即交接（不需要问用户） |
| ≥ 25% | 当前任务已有阶段性成果、且下一步与本次关联不大时交接，否则继续 |
| < 25% | 继续工作，不交接 |

- **脚本失败（failback）**：脚本不可用时，改为观察回复中是否出现"引用早期指令 / 需要追问澄清 / 回溯性措辞"等上下文模糊信号，触发则交接。

### 场景 B：用户发起（直接交接）

- **B1 明确指令**（"交接 / handoff / 开新会话"）→ 直接生成交接摘要并开新会话。
- **B2 模糊意向** → 先确认，用户点头后执行。

### 交接摘要

交接前自动生成结构化摘要，包含：

- **当前状态**：项目/任务现在处于什么位置。
- **已确认的事实**：旧会话花 Token 搞清楚的事实，直接固化，避免新会话重复探索。
- **待处理的工作**：只描述方向，不限定具体做法。
- **已知的坑**：已踩过的报错/依赖/权限问题，新会话不用再踩。
- **会话目标**：通过 `/goal` 重建，文本照抄旧目标。
- **会话级状态**：todos 与 `.omo/plans/` 计划文件。

### 交接后的系统清理（防止旧会话被拉起）

交接不是口头承诺。助手会按以下**不可颠倒**的顺序把系统状态清理到与"已交接"一致，**全部完成后才输出结束语**：

1. 执行 `/stop-continuation`（停 ralph loop / todo continuation / boulder）；
2. 用 `todowrite` 清空所有 todo（completed / cancelled）；
3. 用 `update_goal(status="complete")` 关闭 active goal（**不传 `session_id`**，缺省即当前会话；失败时 `/goal clear` 兜底）；
4. 停用/移除拉起本会话的定时任务；
5. 验证：`get_goal` 无 active goal、todo 无 pending/in_progress；
6. 最后输出"✅ 本会话已交接。本会话结束。"

交接完成后旧会话**永久终止**：无论被何方式拉起，只回复"已交接并结束"并再次清理，绝不继续任何任务。

## 上下文占用率脚本（可选）

`scripts/calc_ctx_use_rate.ps1` 是一个一次性上下文占用率报告脚本：

- 通过 opencode 本地服务查询指定会话的最近一轮 token 消耗，对比模型上下文窗口，输出占用率百分比。
- 需要环境变量 `OPENCODE_SERVER_USERNAME` / `OPENCODE_SERVER_PASSWORD`（opencode server 的访问凭据）。
- 会话 ID 缺省时自动选取当前目录下最近更新的会话。

```powershell
# 指定会话
powershell -NoProfile -ExecutionPolicy Bypass -File "scripts\calc_ctx_use_rate.ps1" -SessionId <当前会话ID>
```

> 该脚本只在持续工作模式（场景 A）下被调用。场景 B（用户主动交接）不依赖它。

## 注意事项

### Goal 清理的正确姿势

关闭 goal 时**不要**尝试显式传 `session_id`——助手通常拿不到正确的 opencode 会话 ID，误传其他会话 ID（尤其 OpenChamber 新会话 ID）会导致 goal 关不掉，旧会话被 goal 机制反复拉起、与新会话冲突。`update_goal(status="complete")` 不传参（缺省即当前会话）是最可靠的方式，失败再 `/goal clear` 兜底。

### 交接前的系统状态清理

在输出"本会话已结束"之前，必须先完成全部清理（stop-continuation → todo → goal → schedule → 验证）。一旦先输出结束语，助手容易提前停手而跳过清理——这是旧会话被反复拉起的头号原因。

### 交接摘要的纪律

- 内容一律从当前可见对话提取，**禁止编造**。
- "待处理的工作"只写方向，不写实现细节，具体怎么做由新会话自行判断。
- 若无 active goal / 无未完成任务，对应段落整段删除。

### 自主交接的边界

- 禁止在非段落边界执行上下文查询。
- 禁止在占用率 < 25% 时执行自主交接。
- 用户明确表示"不要交接"后，禁止自主交接，除非用户再次明确指令。

### 与 OpenChamber / OhMyOpenCode 的关系

本技能的核心动作分属两个不同系统，**这正是[适用前提](#适用前提设计边界)所依赖的能力**：

- **goal 机制（`/goal`、`create_goal`/`get_goal`/`update_goal`）与 `/stop-continuation`** → 由 **OhMyOpenCode（OMO）** 提供，用于交接后的系统状态清理与续跑控制。
- **会话创建与注入（`session.create` / `session.send`）** → 由 **OpenChamber** 提供，用于把交接摘要送进新会话。

若脱离此环境，技能退化为"纯摘要输出"模式：助手将交接摘要直接输出给用户、由用户手动开新会话粘贴，且无法自动清理旧会话的 goal / todo / continuation。
